# Changelog

All notable changes to structural. Format follows
[keep-a-changelog](https://keepachangelog.com); one line per feature. The
project is unreleased, so everything lives under *Unreleased* for now. For
how the system works, see [`docs/`](docs/); for the narrative behind a
change, see [`journal/`](journal/); for what is left, see
[`backlog/`](backlog/).

## [Unreleased]

### Added
- **Workspaces re-run discovery on filesystem events** (docs/observation.md): every workspace watches its own root, and a batch — including an overflow — reduces to a full evidence re-gather and re-select, so a tree that grows a language gets its server slot without a restart. Append-only, warms nothing; not a freshness claim.
- **Signal policy over the watcher** (docs/observation.md): binding and queries are strong signals that start servers; filesystem batches are weak — they refresh evidence and warm only a newly appeared language's server, and only while an agent is attached, so build output and background churn launch nothing. A new slot is reachable by demand in the same breath: the refresh grows the entry's slot copy under the workspace lock.
- **Idle eviction** (docs/observation.md): a server no strong signal has addressed for the interval — default 30 minutes, `idle_eviction_secs` in `structural.toml` — stops while observation goes on; the next query reacquires what it needs, and a failed ladder retries on the same clock. A launch superseded by a stop cannot publish over its slot: slot generations are compared at publish.
- **A lost watcher degrades instead of dying** (docs/observation.md): a watch failure ends the refreshes, not the thread — the idle sweep keeps running and every sweep re-attempts the watch, logging the loss and the recovery once each. A workspace whose last session drops closes its watcher at once.
- **A bare-name query is told what the watcher delivered** (docs/correctness.md): before any index is read, a query sends every filesystem change the watcher delivered before it was admitted to the servers that would answer it, as `workspace/didChangeWatchedFiles` — reduced to each path's state now, never for a document the server holds or for build output, on top of each server's own watcher, and with a full re-statement after a lost event. What that does not cover — a change not yet delivered, and a server's index still catching up — is stated in the doc.
- **Every query is current with the disk** (docs/correctness.md): each server keeps a census of the files it serves, taken before its process spawns and re-taken at every query; whatever was written, created or deleted since is pushed as content or closed before any index is read, so an edit made just before a bare-name query is seen without waiting on the platform's change delivery — validated on rust-analyzer and pyright, and a miss in a tree past the walk budget says so.
- **`references` scopes and pages its listing** (docs/tools.md): `within` lists only the references under a file or directory, counted against the whole; a listing past 100 says which window it shows, summarizes the rest by directory largest-first, and names the `page` that continues it.
- **`focus` matches whole identifiers first** (docs/resolution.md): an occurrence counts where it is not continued by an identifier character (Unicode alphanumeric or `_`), falling back to plain substrings only when none is, so `boundaries` no longer collides with `extract_boundaries`.
- **`expanded` on a derive says which case it is** (docs/servers.md): rust-analyzer expands a proc-macro derive at the derived trait's name and returns nothing for builtin derives or for `derive` itself, and the answer now says so instead of "not a macro call".
- **Outlines page, survey directories, and leave locals out** (docs/tools.md): an outline past 200 lines continues with `page`, each later page opening with the ancestors of its first line; a `path` naming a directory outlines every served file under it with its top-level items, saying what it left out; and a variable or constant under a function is a local, counted in the header rather than listed — a function's own outline still lists them.
- **A module path qualifies a name** (docs/resolution.md): `tools::listing::render`, `pkg.listing.render`, `observation::reduce` for `observation/mod.rs`, and `tests::helper` for an inline `mod tests` resolve from the candidate's file path, its file's outline and its directory, keeping only the closest match and listing ties; a qualifier that matches nothing says what qualifiers are matched against.
- **Location views set tests and the outside apart** (docs/tools.md): `implementations`, `incoming-calls` and `outgoing-calls` list tests under `tests (heuristic)` through the same classifier as `references`, and callees outside the workspace root come last as one line each naming the lines that call them, without their toolchain or dependency paths.
- **An operator channel** (docs/operator.md): facts an agent cannot act on — a candidate that failed, a ladder exhausted, a fallback, a language no server serves, a bad `structural.toml`, an idle release, a lost or recovered watcher — go once, at the transition, to an `Operator` sink set with `Host::with_operator`, as structured events; the default sink writes one stderr line each, and the MCP front end also sends them as MCP logging (`notifications/message`), holding up to 64 from before the client's handshake.

### Fixed
- **A candidate in a deleted file is excluded, not navigated** (docs/correctness.md): an index that has not yet applied a deletion — rust-analyzer applies one after the query that follows the notice — no longer fails the query trying to read the file; the candidate is counted in a note instead.
- **A name a server decorated still resolves** (docs/resolution.md): when nothing matches the queried name, a candidate whose advertised name mentions it exactly once as a whole token nominates under the identifier — `choose/1` from both Erlang servers, `int choose(bool flag)` from ccls — with every range check made against the identifier, and no language-specific parsing. Erlang goes 1/8 to 3/8 on both servers, vtsls 5/8 to 8/8.
- **A server that reserves a progress token it never uses** (docs/servers.md): `window/workDoneProgress/create` counts as outstanding work by default, but `progress_create_is_work = false` says a server reserves a token and never reports through it — ccls creates one `index` token at startup and sends no `$/progress` at all, which left every readiness wait on it blocking forever. ccls goes from 0/8 (hanging) to 6/8, ahead of clangd's 5/8.
- **Binding no longer waits for a language server** (docs/ownership.md): `agent_started` starts every configured server and joins none of them, so `structural serve` answers `initialize` in milliseconds instead of behind a full handshake plus index warm-up — 13s on a warm rust-analyzer here, past an MCP client's 30s negotiation window on a cold one. The first tool call still waits for the launches.
- **An anchor with no `focus`** (docs/resolution.md): the name is what the definition carries rather than how the anchor spelled it, so `choose(Mode::Fast);` resolves to `choose` instead of erroring that the server's target "does not name it in the file on disk".

### Added
- **Catalogue synthesis** (docs/catalogue.md): the per-language measured set and order — what the probes answered through our own tools, ties broken on dataset consensus then name, no admission threshold — with the cuts (diagnostics-only servers, argv-less records, markup trees) and the arbitration stated with what each choice beat; eight breadth candidates joined the harness, and all thirteen harness languages have checked-in evidence.
- **show answers the definition site** (docs/resolution.md): when a server answers both `definition` and `declaration` and the two agree somewhere other than the index candidate, the answer stays at the candidate — a bare C++ name shows the body instead of the header signature; anything else keeps the hop, one hop and never a chase.
- **A server that answers nothing is named on the miss** (docs/resolution.md): a miss over servers that advertised an index but answered nothing all session names them and says the project may not be set up for their languages, instead of reporting the symbol absent — one yielded candidate or outline answer extinguishes it.
- **A directory scope over unserved languages names them** (docs/resolution.md): a directory scope that missed on every running server says which extensions the directory holds and which no running server serves — routing, not absence — instead of reporting the symbol absent.
- **A server that will not start falls back to the next candidate** (docs/discovery.md, docs/ownership.md): a slot holds its plan's whole ladder in rank order and one launch walks it, bounded by the list, retaining every failure — so a candidate that spawns and then fails its handshake is stepped over, and both the message and the result footer say what was tried.

- **Workspaces are keyed by the project root** (docs/discovery.md, docs/ownership.md): two agents in sibling members of one cargo workspace share a server instead of each starting one that indexes the whole workspace anyway, while each session keeps its working directory as the view `path`, filtering and rendering are relative to. `structural.toml` is now read from the project root.

- **Slots come from plans** (docs/discovery.md, docs/ownership.md): a workspace lays out a slot per planned server rather than per configured adapter, so a Python-only tree starts no Rust server; `structural.toml` becomes the override layer over the catalogue and gains `disabled = true`, which it could not express before.

- **Discovery, as pure policy** (docs/discovery.md): evidence + catalogue + overrides → server plans with reasons, a value no process is started from — ranked by what a server answered through `definition`, `references` and `rename` rather than by how many editors ship it, with no admission threshold and no score statable without the run that produced it.

- **No-index note** (docs/resolution.md): a name that missed says which languages have no symbol index to ask — pylsp, gleam and qmlls serve documents and no index — and that naming their file in `path` resolves from its outline, instead of reporting the symbol absent.

- **TypeScript and C++ conformance columns** (process/testing.md): eleven servers across five languages measured, reduced to the dimensions they vary in (reference/lsp-server-conventions.md) and four aggregate units (backlog/generic-baseline/).

- **Rust and Go conformance columns** (process/testing.md): the probe is per-language — rust-analyzer answers 8/8, gopls 6/8, and the Go failures are `backlog/server-spelled-qualified-names.md`.

- **Fixtures as a specification** (src/fixtures.rs): the trees are checked in as `.in` text and materialized into scratch directories rather than living in the repository, so structural pointed at itself sees one language; `cargo run --bin fixtures -- <dir>` writes them out to work on by hand.

- **Qualified-name scope note** (docs/resolution.md): a qualified name that missed the symbol index says that naming the declaring file in `path` resolves the qualifier from that file's outline — the index carries at most one `containerName` per symbol and several servers report none, where `documentSymbol` nests.

- **The generated catalogue** (docs/discovery.md): `src/bin/catalogue.rs` emits every measured server from the checked-in evidence into shipped entries — 13 languages, 32 servers, score provenance and consensus carried, a drift test against the stated order — and an override now configures a known server in place (its measurement retained) instead of demoting it, so a named server outranks the catalogue as the precedence table says.
- **Paired probe columns** (process/testing.md): `qualified name, in file` alongside `qualified name`, so a failing cell localizes to the index or the outline rather than being ambiguous between the server and this code.

- **Conformance probe** (process/testing.md): `tests/conformance/` asks every installed server of a language the questions `definition`, `references` and `rename` need, and prints a scorecard with each server's version — what it answered, not what it advertises.
- **Checked-in score evidence** (process/testing.md, docs/catalogue.md): every conformance run writes `tests/conformance/scores/<language>.json` — per-probe outcome vectors with server version, structural revision, fixture revision, date and machine — so a preference order's evidence is a reviewable diff rather than a printed-and-discarded card.

- **Bare-name staleness regression** (process/testing.md): feature-gated pending acceptance — an unopened-file edit and a newly-created file, each followed immediately by a bare-name query — observed failing on rust-analyzer, with the currentness wording qualified to match the implementation (docs/correctness.md).
- **`rename`** (docs/tools.md): an LSP rename previewed with a digest over the files it touches, applied only when the digest still matches, with the servers re-synced afterwards.
- **Rename caveat note** (docs/tools.md): an adapter-declared `rename_note` rides as a `note:` line on every rename preview and applied summary — rust-analyzer's rename edit covers code only, so the caller is told to check doc comments for the old name.
- **`definition` views** (docs/tools.md): `outline`, `implementations`, `incoming-calls`, `outgoing-calls`, `type` (via rust-analyzer's `hoverRange`, so an anchor yields the type of the expression), plus rust-analyzer's `expanded` and `related-tests`, which returns a runnable cargo command per test.
- **File-scoped nomination** (docs/resolution.md): a `path` naming a file nominates from that file's own `documentSymbol` instead of filtering the servers' bounded `workspace/symbol` response, so a common qualified name resolves from the file that declares it — the candidate is the name the server advertises and the file's own text is what verifies it; a directory scope still narrows the index.
- **Qualified names and anchors** (docs/resolution.md): `Config::new` filters candidates by the container the server reports; an anchor quoted from a file — with `focus` naming the token — skips the symbol index and reaches locals, parameters and call sites.
- **`references`** (docs/tools.md): find-all-references to a resolved identity, one source line per hit with its enclosing item, grouped by file, tests set apart by a heuristic that says it is one, with every hit's range verified against the text just read.
- **LSP tool names and jobs-first docs** (docs/tools.md): `show`/`uses`/`action` become `definition`/`references`/`rename` — go-to-definition, find-all-references, rename — with the `rename` tool dropping its `action` dispatch field; tool titles, descriptions, and server instructions lead with the grep/read replacement and a copy-pasteable `{"symbol": "Config::new"}` before the scoping rules and caveats, and each tool carries worked `examples` on its input schema (mcplease `ToolMeta::examples`).
- **Externally escalatable shutdown** (docs/shutdown.md): `request_shutdown` closes admission without waiting, `force_shutdown` interrupts starting and running servers without taking a workspace lock, `wait_shutdown` waits for admitted work and cleanup. Unix signals escalate — first soft, subsequent force — and real input EOF forces cleanup in the reader.
- **Owned process groups** (docs/shutdown.md): on Unix each server leads its own process group, and cleanup signals the group before reaping its leader, so descendants holding inherited pipes do not survive teardown.
- **Explicit server lifecycle** (docs/ownership.md): `Cold | Starting | Running | Failed` per slot, with concurrent demand electing exactly one launcher, launches running on their own threads holding no lock while they spawn and initialize, publication bounded so a busy workspace cannot strand a child, and every exit path — including a panic — waking the waiters.
- **The shared host** (docs/ownership.md): workspaces keyed by canonical root and shared by every caller bound to one, with per-agent interest, per-workspace serialization, and independent progress across unrelated roots. One MCP process and an embedded consumer's many agents enter through the same door.
- **The adapter seam, pyright, and `structural.toml`** (docs/servers.md): per-server knowledge behind an `Adapter` trait — command, languages, capabilities, readiness policy, query rewriting, extra views — with built-ins overridable and any other command configurable as a generic server.
- **The threaded LSP handle** (docs/transport.md): one server on reader/owner/writer threads with every queue bounded, one inactivity backstop as the only timer, and a `$/structural/ping` liveness probe so a quiet-but-busy server is not mistaken for a broken one.
- **`show`** (docs/tools.md): a symbol resolved to its definition's decorated source — doc comments and attributes included — with the extent from the server's `documentSymbol` and tree-sitter widening it over leading decorations.


### Changed
- **Resolution is by identity, not by name** (docs/resolution.md): every exact `workspace/symbol` candidate is sent to `definition` and the results grouped by target, so candidates that navigate to the same place are one answer and candidates that differ are an ambiguous listing with kinds, paths and signatures. Nothing is silently picked.
- **Answers are trimmed to what an agent needs** (docs/correctness.md): one header line plus the body on the happy path, one line per listing entry, `note:` lines only when something is degraded, and the standing caveats stated once in the tool descriptions rather than in every result.
- **rust-analyzer's symbol search is configured `all_symbols` with `excludeImports`** (docs/servers.md): the default searches types first and reports re-exports as symbols, which made some functions unreachable and every re-exported name ambiguous.
- **Every source file stays under about 500 lines** (CLAUDE.md), with tests in a sibling module.

### Fixed
- **A qualifier resolves from any source that carries it** (docs/resolution.md): `containerName`, an outline's nesting, the symbol's own name, or the file when a module is a file — any one confirming the qualifier is enough. gopls spells a method `Config.Doubled` and answers 8 of 8 probes where it answered 6; gleam and qmlls resolve a file-scoped qualified name they could not.

- **`implementations` renders a derive as one row** (docs/tools.md): a derived trait is one implementation result per trait, all at the `#[derive(…)]` line with nothing to tell them apart, so the identical rows fold into the one that names the traits and a `note:` says how many folded; the header keeps the server's count.

- **A cold symbol index no longer reads as a missing symbol** (docs/servers.md): a launcher opens one file the server serves and asks for its outline before publishing it, so a bare name resolves on a fresh session — pyright and basedpyright answer 8 of 8 probes where they answered 7, and five more servers gained their cold bare-name column.

- **A server that needs client settings can be given them** (docs/servers.md): `settings` in a `structural.toml` entry answers the server's `workspace/configuration` request, which some servers read and nothing else substitutes for — deno 2.9.6 served nothing at all for a whole session without it, and answers 6 of 8 probes with it.

- **An outline container's range may be wider than the name** (docs/correctness.md): the advertised name is located inside the selected text at a token boundary instead of compared for equality, so a server that selects a whole assignment reports a container; zero or several occurrences still refuse, and the refusal no longer names a cause it has not established.

- **A configured override of a built-in keeps all of its knowledge** (docs/servers.md): `Configured` did not forward `outline_container`, `extra_views`, `extra_view_request`, `render_extra_view`, `hover_params` or `reference_aliases`, so naming rust-analyzer in `structural.toml` to point at a specific binary silently lost impl containers, the `expanded`/`related-tests`/`type` views and `Self` aliases.

- **A symbol range wider than the name resolves** (docs/correctness.md): `SymbolInformation.location.range` is the range enclosing the symbol, so a whole-declaration range is conforming; the name is located within it and the follow-up request is sent at the name. A range holding no occurrence is still refused, and two are ambiguous. The refusal no longer claims staleness it has not established.
- **`workspace/symbol` is not sent to a server that did not offer it** (docs/servers.md): a `-32601` used to end the whole query, including file-scoped ones that never needed the index.
- **A refused outline degrades `uses` instead of failing it** (docs/tools.md): the enclosing-item column is dropped with a note saying why, distinguishing a server without `documentSymbol` from one that would not outline an unopened document.
- **The flat `SymbolInformation[]` outline nominates** (docs/resolution.md): its declaration line names the symbol and its `containerName` field names the container, so a file scope resolves against servers that serve that shape.
- **A blocked tool call no longer blocks MCP `ping`** (journal/2026-09-14-generic-kernel-and-tools.md): mcplease's stdio server answers `ping`, `initialize` and `tools/list` on its reader thread while tool calls queue, so waiting as long as a server needs does not make the mount unresponsive.
- **A failed connection keeps answering with its reason**: the owner thread lingers as a tombstone instead of exiting, which had turned every later error into "connection closed".
- **A notification blocked behind a server that stopped reading had no backstop**: pending writes are now tracked and expired like requests. Found by deleting the crate-wide `allow(dead_code)`.
